id: RES-2026-001
title: Any user can register applications, enabling illicit consent grants
source: https://learn.microsoft.com/entra/identity/role-based-access-control/delegate-app-roles   published: 2024-01-01   author: Microsoft
services: Entra ID — default user role permissions, application registration, user consent
summary: By default every member user in a tenant can register an application and create a
  service principal. Combined with a permissive user consent setting, an attacker who
  controls or phishes any member account can stand up an application and collect delegated
  access to other users' data without ever touching a privileged account. The registration
  itself is not an attack; it is the precondition that makes consent phishing cheap.
vendor_status: by design per vendor; tenant action required to restrict —
  https://learn.microsoft.com/entra/identity/enterprise-apps/configure-user-consent
exposure_condition: authorizationPolicy.defaultUserRolePermissions.allowedToCreateApps is true,
  AND the tenant's user consent setting permits consent to apps from unverified publishers.
applicability: every Entra tenant. Never not_applicable.
reader_query: |
  GET https://graph.microsoft.com/v1.0/policies/authorizationPolicy
  GET https://graph.microsoft.com/v1.0/policies/permissionGrantPolicies
  Both are collected by scripts/11-collect-entra.sh as
  inventory/entra/authorization-policy.json and permission-grant-policies.json
result_logic: exposed if allowedToCreateApps is true and user consent is not restricted to
  verified publishers with low-impact permissions. not_exposed if either is locked down.
  not_assessable if authorization-policy.json is in NOT_READABLE.tsv.
blind_spots: Global Reader cannot see which applications users have actually consented to
  beyond oauth2PermissionGrants, and cannot see consent request workflow approvals.
false_positives: a tenant that deliberately delegates app registration to a scoped group via
  a custom directory role rather than the default user role. Check directory role assignments
  before rating.
related_baseline: CIS Microsoft Azure Foundations — Entra ID section; MCSB PA-1
recommendation: Set allowedToCreateApps to false and delegate registration through the
  Application Developer role. Restrict user consent to verified publishers.
confidence: high — both properties are directly readable and the vendor documents the behaviour.
